# Shared JSON Schemas

Source of truth for cross-language contracts. TypeScript types and Pydantic models are generated from these files. Owned by workstream A ([MVP_SCOPE.md §3](../docs/MVP_SCOPE.md#3-workstreams-for-parallel-agents)).

| Schema | Version | What it describes |
|---|---|---|
| `common` | `common/1.0` | Shared definitions: ids, confidence, severity, the eight scoring criteria, scores, periods, soil |
| `provenance` | `provenance/1.0` | Source, product, version, resolution, period and quality of a number (C-2) |
| `canonical-series` | `canonical-series/1.0` | One variable at field tier, with per-step quality flags and provenance |
| `field-bundle` | `field-bundle/1.0` | Field Data Bundle: field, series, phenology, layers, context, soil, gaps |
| `engine-input` | `engine-input/1.0` | Candidate rotations, soil, priorities, constraints, scenario, seed |
| `engine-output` | `engine-output/1.0` | Scores per rotation and season, resilience, contributions, Monte Carlo bands |
| `evidence-card` | `evidence-card/1.0` | Evidence Card (F-08): every field is mandatory, every evidence item has a source |
| `assistant-tools` | `assistant-tools/1.0` | Input and output of each browser-side assistant tool |

The knowledge pack schema (`knowledge-pack/1.0`) is TypeScript-only and lives with its packs in `packages/knowledge/src/schema.ts`.

`projection.schema.json` is generated by the science API from its own models and is not part of this set.

Each file has an `$id` (`https://itza.dev/schemas/<name>.schema.json`) and an `x-version` label. Files reference each other by relative path (`common.schema.json#/$defs/Id`).

## Generated code

```bash
pnpm schemas:generate   # rewrite generated files after editing a schema
pnpm schemas:check      # fail when generated files are stale (runs in `pnpm check` and in CI)
```

- TypeScript: `packages/engine/src/contracts/generated/` (`types.ts`, `schemas.ts`). Import `type`s and `validate(schemaId, data)` from `@itza/engine/contracts`.
- Python: `services/science-api/src/itza_science/contracts/` (Pydantic v2 models, one module per schema).

Never edit generated files. Commit them with the schema change.

## Fixtures

`fixtures/synthetic/` holds two invented Field Data Bundles and one example document per schema. Tests in both languages validate them and check that bad documents are rejected. Regenerate the bundles with `node fixtures/synthetic/generate.mjs`.

## Change rules

- Before the contract freeze (schemas v1.0): edit in place and regenerate.
- After the freeze: any change that is not purely additive needs a version bump of the schema (`x-version`, and the `schema` constant where the document carries one), a migration note in this file, and all consumers updated in the same PR. Additive changes (a new optional property) keep the version.
- Cross-cutting contract changes always go through this folder, never through a consumer's private copy.

### Unavailable terrain metadata (#13)

`field.elevation_m` and `field.slope_mean_deg` accept `null` when terrain has not
been retrieved. Producers must include a matching `gaps` entry; zero is a measured
value, not a missing-data sentinel. Existing numeric bundles remain valid. Types
are regenerated together; the engine rejects missing elevation before computing ET0.
